# Учебный модуль заявок: PHP + React

Время: ориентир 3–4 часа работы. Использование ИИ разрешено.
Все данные вымышлены. Задание не подключается к системам Airnet.

## Запуск

Нужен Docker с Compose v2. Из корня проекта:

```sh
docker compose up --build
```

Откройте http://localhost:5173. При первом запуске скачиваются образы,
устанавливаются зависимости и автоматически создаётся учебная БД.
Выберите роль и нажмите «Войти». Пароля нет: это готовая учебная авторизация.
Роль «Просмотр» соответствует Анне Примеровой, «Редактор» — Илье Учебному.

Файлы PHP и React подключены как тома: изменения видны без пересборки образов.
Если меняете зависимости, перезапустите frontend:

```sh
docker compose restart frontend
```

Посмотреть состояние и журналы:

```sh
docker compose ps
docker compose logs api
```

Восстановить начальные источники и очистить историю:

```sh
docker compose exec -T db psql -U assessment -d airnet_assessment < database/reset.sql
```

Остановить приложение:

```sh
docker compose down
```

Для полного пересоздания учебной БД используйте `docker compose down -v`
и запустите проект заново. Это удаляет только тома этого Compose-проекта.

Инструкция запуска без Docker: [docs/local.md](docs/local.md).

## Ситуация

Сервисная служба использует список заявок и карточку со сменой источника.
Пользователи сообщили о трёх проблемах:

1. При быстром переключении иногда открываются данные предыдущей заявки.
2. Карточка заявки без источника загружается с ошибкой.
3. Сотрудник с правом только на просмотр смог изменить источник.

Воспроизведите проблемы, найдите причины и исправьте их. Затем доведите
смену источника до поведения ниже. Места ошибок в коде не указаны.

До изменений создайте Git-репозиторий и сохраните исходное состояние первым
коммитом. Это позволит показать небольшой diff вашего решения.

## Требуемое поведение

- Пользователь с `FUNC_TICKETS_VIEW` видит список, карточку и историю.
- Изменение разрешено только с `FUNC_TICKETS_SOURCE_EDIT`. Сервер проверяет
  право независимо от состояния кнопки и переданных клиентом полей.
- Архивная заявка доступна только для чтения для обеих учебных ролей.
- Новый источник — положительный целочисленный id из `sources`.
  Строки, дроби, `null`, отсутствующее поле и неизвестные id отклоняются.
  Снимать источник этим действием не требуется.
- Отсутствующий источник отображается как «Не указан» и не ломает API.
  В JSON карточки `source` в этом случае равен `null`.
- Изменение и запись истории сохраняются атомарно. История содержит
  сотрудника из серверной сессии, прежний и новый источник и время изменения.
  Отправленные клиентом имя, id сотрудника или права не дают полномочий.
- Повторный выбор текущего источника возвращает успех без новой записи истории.
- Ошибки API возвращаются как JSON. Нет сессии — 401; недостаточно прав или
  архивная заявка — 403; некорректный ввод — 400; отсутствующая заявка — 404.
  При серверной ошибке — 500 без раскрытия внутренних деталей.
- React показывает загрузку и ошибки, предотвращает повторное сохранение
  во время запроса и не отображает устаревшие ответы при переключениях.
  Ответ сохранения предыдущей заявки также не должен подменить текущую карточку.
- После успешного изменения обновляются карточка, список и история.

При недостатке прав запрос должен быть отклонён до изменения данных.
Для пользователя с правом редактирования сначала проверяется наличие заявки,
затем запрет архива, затем корректность источника.

## Ограничения

PHP 7.4, `pg_query_params`, PostgreSQL и React. Сохраните существующий стек.
Новые фреймворки, полная переработка проекта и улучшение дизайна не нужны.
Учебную авторизацию, CSRF и настройку окружения переписывать не требуется.
Задержки API нужны для воспроизведения переключений; не убирайте их вместо
исправления работы с ответами. Проверки должны работать и с включёнными
задержками, и без них.

Защита от потери изменений при одновременном редактировании двумя
сотрудниками не входит в обязательную часть. Опишите, что сейчас произойдёт
в таком случае. Дополнительные функции не компенсируют ошибки в обязательных.

## Что сдать

1. Git-репозиторий с исходниками и понятными изменениями, без `node_modules`.
2. Заполняемые файлы [SOLUTION.md](SOLUTION.md) и [AI_USAGE.md](AI_USAGE.md).
3. Автоматические проверки важных сценариев и команду их запуска.
   Хотя бы одна проверка должна воспроизводить исходную ошибку и проходить
   после исправления. Проверяйте поведение, а не наличие определённых строк кода.

Готовая проверка запуска:

```sh
python3 tools/smoke.py http://localhost:5173
```

Она проверяет только инфраструктуру и базовые маршруты, а не решение задания.

Если за 4 часа не закончили, сдайте текущее состояние. Укажите приоритеты,
выполненные проверки и оставшиеся ограничения. Время развёртывания при
проблемах с Docker отметьте отдельно; обратитесь к нам, если запуск не удаётся.

## ИИ и обсуждение результата

ИИ, документация и любые средства разработки разрешены. Вы отвечаете за
весь сданный код. В `AI_USAGE.md` приведите один существенный пример работы
с ИИ и способ проверки результата. Если не использовали ИИ, так и напишите.
Историю всех чатов предоставлять не требуется.

На собеседовании будет разбор решения и небольшое изменение требования.
Первые 15 минут изменения выполняются без ИИ, с доступом к документации;
затем ИИ разрешён. Оценим понимание и ход работы, а не скорость печати.
